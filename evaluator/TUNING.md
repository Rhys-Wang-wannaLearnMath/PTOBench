# Per-Case Candidate tuning

`evaluator/tuning_policies.json` is the authoritative per-Case option inventory.
It is generated by `inventory_tuning.py` from the installed compiler/runtime APIs
and the canonical Seed's conservatively reachable Python source closure. The
read-only workspace `.benchmark_context/tuning_capabilities.json` gives the Agent
its own Case's defaults, editable controls, allowed values, units and restrictions.
A declared editable value is an optimization permission, not a pre-certified
correctness or performance claim. Changed Candidates/settings must pass evaluate.

Every new workspace receives its Case's complete default `tuning.json`. Its
read-only `README.md` and `tuning_capabilities.json` describe only the permitted
editable fields, including type, unit, compile/dispatch stage, effect and limits.
Basic and CANNBot main/child prompts point to this Case-specific inventory.
The two compiler defaults stay `PYPTO + false`; complete defaults vary by Case.

The Agent-facing `default_configuration_validation` records correctness and
clean baseline status for the registered starting implementation under its full
defaults. It is `passed` only when the baseline matches the current source,
contract, comparator, configuration, environment and static policy identity,
records the complete requested defaults and has complete positive timing samples.
`reference.json` carries the same validation summary. The legacy
`hardware_tested_in_this_change` flag reflects this default validation only;
`other_values_verified` stays false. Static capability inspection alone makes
no hardware claim and remains independent of measurement results, preserving the
identities attached to existing evidence. Hidden tensors and internal evidence
paths are not copied into the Agent's context.

| Control | Default | Permission and applicability |
| --- | --- | --- |
| `memory_planner` | `PYPTO` | `PYPTO`, `DSA_RP`, `PTOAS`; local tile memory planning |
| `analyze_auto_scopes_for_deps` | `false` | Boolean where reachable orchestration can generate AUTO scopes; manual regions are skipped |
| `ring_task_window` | `16384` where exposed | Task-producing a2a3 orchestration only; `16384` or `32768` slots per ring; never shrink the existing window |
| `aicpu_thread_num` | `4` where exposed | Single-card task-producing a2a3 paths only; `2`, `3`, `4`; distributed paths obtain threads from a different configuration and remain managed |
| `strategy` | `Default` | Fixed: no alternative installed strategy |
| `enable_pypto_l0c_double_buffer` | Existing compiler default, off for PYPTO | Withheld: upstream experimental flag, known chained Mat-scratch buffer overflow (#1908), missing RunConfig field |
| `runtime` | Existing tensormap/ringbuffer ABI | Fixed: graph ABI changes also require different worker binding/execution semantics |
| Arbitrary pass options | Existing default pipeline | Withheld: no typed adapter; changing pass ordering can break IR invariants |
| `ring_heap`, `ring_dep_pool` | Inherit | Managed: output allocation and dependency capacities; arbitrary reductions can stall/fail, growth consumes HBM |
| Target, device IDs, distributed workers, tolerances | Existing Case contract | Managed; not optimization controls |
| Dumps, source locations, compiler verification and diagnostics | Existing profile policy | Not tuning; do not perturb clean timing or weaken checks |

The installed a2a3 runtime source establishes a task window of 16384 per ring and
an architecture maximum/default of 4 AICPU threads. Only the bounded scalar task
window interface is exposed; no per-ring arrays or arbitrary sizes. The largest
allowed window doubles task capacity; it does not enlarge output heaps or
edge pools. Baseline testing is of defaults only, so a nondefault allocation can
still fail on a particular Candidate and is never promised faster or universally
safe. Maintainer queue attempts have a 30-minute timeout and owned-process cleanup.

The initial inventory contains 311 Cases: all retain the two established compiler
controls; 295 additionally expose task window and 206 expose AICPU threads. Case
option sets differ. Reachability excludes unused functions, follows local imported
entry points and helpers, and records source locations and content hashes. It
cannot prove that every potential site survives lowering, nor that changing a
parameter improves latency. The installed compiler has no additional stable,
typed, low-risk pass tuning interface beyond the controls reviewed above. This
is deliberately not an arbitrary pass/environment-variable interface.

Unexposed fields inherit Case runtime, then environment runtime, then native
compiled/runtime defaults. Eight Cases' inherited `enable_dep_gen=true` clean
settings are preserved and reported. The three diagnostic profiles are unchanged:
`runtime`, `hardware` (public `pmu`), `compile` (public `compiler`). Diagnostics do
not add editable tuning controls.

The entire path is Case-aware: workspace creation and fork, pre-budget validation,
RunConfig creation, isolated evaluation, evaluate, all diagnostic modes and final
Snapshot execution. The policy JSON is copied into the isolated runtime. The
compiler adapter and native CallConfig boundary are checked separately: compile
controls must reach `compile_kwargs`, dispatch controls must reach actual native
fields. Unknown options, invalid types and values outside that Case's list fail
before hardware admission. Duplicate keys, symlinks and oversized tuning files
remain rejected. The requested full configuration and resolved runtime fields are
recorded in `execution.json` and each result's `measurement_config.tuning`.

Final acceptance uses the selected Snapshot's frozen `tuning.json`, together with
its source. It does not replace Agent settings with baseline defaults. The Ref
baseline always uses the registered Case defaults, including `PYPTO + false`.
Sessions captured under older policies must be recreated; their protection backup
must not restore old evaluator code or old Case permissions.

Static commands (no Candidate imports, compilation or device dispatch):

```bash
python evaluator/inventory_tuning.py
python evaluator/audit_tuning.py --output reports/tuning/case_interface_audit.json
python -m unittest discover -s evaluator/tests -p test_tuning.py
```

The per-Case inventory and option decisions are retained in
`reports/tuning/case_option_inventory.json`. The interface audit checks each Case
under clean and all three profile modes, including bounded new dispatch settings.
CPU tests use real RunConfig and native CallConfig objects, with no Worker/device
launch. Representative hardware results are never assigned to other Cases.

A serial maintenance queue verifies only each Case's complete default configuration:

```bash
python evaluator/verify_tuning.py --prepare
python evaluator/verify_tuning.py
```

The ledger is `reports/tuning/case_defaults_verification.json`; raw command,
stdout/stderr, source/tuning, execution records and timings are under
`runs/tuning_case_defaults/`. The completed run contains 311/311 fresh PASS
results and published default baselines, including fresh tests of the 13 Cases
that initially reused old baselines. Every Case was compiled, checked for
correctness and measured with its complete default configuration. Additional
allowed values were not all hardware-tested. A future queue preparation may
reuse an already matching baseline; that is distinct from a fresh hardware run.
The earlier `reports/tuning/defaults_verification.json` is a historical
preparation/reuse inventory; the current acceptance ledger is
`reports/tuning/case_defaults_verification.json`.

Each missing default run compiles, checks against the unchanged official fixture
outputs/comparator, then measures clean performance using full formal Case
warmups/rounds. Baselines are promoted only after all of those pass and after
checking the canonical Seed is identical to the Ref Python closure. Previous
`ref_performance.json` is archived in the job before atomic publication. New
baseline records include the full defaults, requested/resolved settings, Case,
source/configuration/comparator/environment/policy identities and evidence path.
Agent Session preflight requires the baseline to match current Case defaults.
Failed runs never replace the baseline. No fixture/oracle/comparator is modified.

The queue takes the shared execution lock, waits for the required devices to
positively report no NPU processes, and never resets a device or kills unrelated
processes. Timeout, incomplete attempt, environment/source/policy change and
infrastructure errors stop for inspection. `--limit N` runs a pilot. Creating
`runs/tuning_case_defaults/STOP` pauses safely after the current attempt completes.

The old six-combination sweep remains archived and paused in
`reports/tuning/hardware_verification.json` / `runs/tuning_verification/`.
It is not an acceptance prerequisite. Its interrupt is recorded separately from
Case failures. `--scope combinations` remains an explicit diagnostic command;
start a new report when its source/default identities no longer match.
