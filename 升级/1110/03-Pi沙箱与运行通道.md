# Pi 沙箱与运行通道 Implementation Plan

> 状态：已完成（2026-11-13）。18 项实现步骤与 Plan 03 最终验收清单均已完成。聚焦非 workload 选择 49 passed、6 subtests passed，含 Node Runtime 探针；CANNBot Pi bundle 定向单测修复后 1 passed。真实 Pi/Pi Shell/Broker CLI 的单 Case Evaluate 与 Combined Profile 均通过，产物位于 `runs/plan03_pi_acceptance_20261112/deepseek_v4.rmsnorm_decode_demo/20261112T151032Z_37b0b0f881ed/`。整文件非 workload pytest 选择的另外 11 项失败（7 项旧 Codex 路径期望、4 项 Python 假 Pi CLI 夹具）归入 Plan 04，不作为 Plan 03 验收门槛；Plan 03 未运行性能 baseline、CV 或 311-Case，也未进入 Plan 04。

**目标：** 让 Basic/CANNBot Pi 以专用 Agent 用户运行，同时只看到当前 Session 的真实 Workspace，并保持 Pi 私有文件、Socket、Gateway、CLI 和网络边界。

**架构：** 复用 `isolation.agent_command` 与 `View.argv`，外层只挂载当前 Session 的真实 `workspaces/` 一个 RW bind。Pi Shell 子 Sandbox 重建只读系统根后，只把同一个 Workspace 根 bind 回去一次；不挂 Candidate 池或 public 副本。共享组控制 Candidate、Context/Outputs 和必要 Socket 的 DAC，Bubblewrap 控制可见路径。Broker、Gateway、Candidate Worker 和 NPU/HCCL 不切换账号。

**唯一运行路径：** 所有受支持的 Pi Agent 启动均须经专用 Agent 用户和 Bubblewrap。关闭沙箱、非 Pi backend 或不完整配置必须报错退出；不得调用旧 runner、以 Broker 身份启动 Agent、解析旧启动配置或切换到旧导出 Workspace。

**依赖：** Plan 01、02 完成；临时 Workspace DAC 已通过。

**Tech Stack：** Linux Bubblewrap/user namespace、Python、Pi/Node、Unix sockets 与 pytest。

**Spec：** [`00-overview.md`](00-overview.md)，尤其是 Pi 文件视图、网络与运行通道边界。

## 全局约束

- 只支持 Pi 后端；Agent 启动始终使用专用账号和 Bubblewrap，失败时停止。
- Agent 只挂当前 Session 的真实 `workspaces/`；Broker、Candidate Worker、Gateway 与 NPU/HCCL 保持原身份。
- 保留 File Guard、Gateway、Broker Socket、CLI、Snapshot 和现有模型通道合同。本地 `PYPTO_PROVIDER_API_KEY` 是协议兼容用的占位值，不是 Gateway 认证凭据；访问控制由 Broker-owned Unix Socket 的 owner/group/mode 与 Bubblewrap 可见性提供。真实上游 Provider API Key 不进入 Pi Agent 环境、启动 Request、Pi 配置、Session 配置或日志。此保证针对 Pi Agent 视图；Candidate Worker 与 Gateway 同属 Broker UID，Worker 进程状态不纳入本计划保证。

## Review Focus

- Native Pi 文件工具、Shell/Python 与 `/proc`/链接路径都不能绕过私有文件和 mount 边界。
- Pi 原生 Session 数据必须可写且可归档；Broker 创建的配置/工具文件保持只读。
- Agent 的可见系统依赖必须可用，但不能因此暴露 Broker HOME、其他 Session 或 PTOBench 内部源码。
