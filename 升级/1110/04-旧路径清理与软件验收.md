# 旧路径清理与软件验收 Implementation Plan

**目标：** 删除旧身份映射、旧 Agent runner 与导出 Workspace 路径；保留专用 Agent 用户 dispatcher 作为唯一 Agent 启动入口，并在不占用 NPU 的情况下完成 PTOBench 软件回归。

**架构：** Plan 01–03 的专用用户、真实 Workspace 和 Pi 沙箱已通过后，按全仓调用关系移除旧实现。最终只保留专用 Agent 用户 + Bubblewrap + POSIX DAC 一条 Agent 路径；不留旧配置、兼容分支或自动回退。固定 dispatcher 是该路径的一部分，不能删除。保持 CLI、Broker、Snapshot、Finalize、Profile 和非 Workspace 归档合同。

**依赖：** Plan 01–03 全部通过。

- Modify `evaluator/agent_launch.py`、`evaluator/isolation.py`、`ops/ptobench-agent-dispatch.py`：删除 subordinate UID/GID、`newuidmap/newgidmap`、临时身份映射代码；保留固定 dispatcher、请求校验和 fail-closed 启动逻辑。

- Modify `evaluator/tests/test_agent_launch.py`、`test_isolation.py`、Workspace/Session/Snapshot 相关测试；更新 Agent-facing README/help。
- 不修改 `modes/cannbot/upstream/ops/` 或 PTOmni/EAT 文档中与 PTOBench 启动无关的同名目录。

## 完成标准与停止条件

真实身份集成、Workspace/Fork/Snapshot、Pi 隔离、CLI/Gateway、Combined/split 和完整软件测试全部通过后进入真实 Pi 验收。任一测试失败、ACL 造成非预期暴露、旧 Agent runner 仍可达或旧隔离可被选择时停止；不得删除失败测试或恢复旧实现来获得通过。
