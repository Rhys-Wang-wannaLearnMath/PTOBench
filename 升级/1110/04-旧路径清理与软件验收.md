# 旧路径清理与软件验收 Implementation Plan

> **For agentic workers:** Use the `executing-plans` skill and implement this plan task by task.

**目标：** 删除旧身份映射、旧 Agent runner、旧 Session 执行兼容与导出 Workspace 路径；保留 `evaluator/agent_dispatch.py` 作为唯一 Agent 启动入口，移除 PTOBench 根目录 `ops/`，令 PTOBench CLI 的 `evaluate` 成为唯一消耗硬件交互预算的操作，并对本 Plan 实际改动的运行路径完成不占 NPU 的定向回归。

**架构：** Plan 01–03 的专用用户、真实 Workspace 和 Pi 沙箱已通过后，按全仓调用关系移除旧实现。最终只保留专用 Agent 用户 + Bubblewrap + POSIX DAC 一条 Agent 路径；不留旧配置解析、迁移适配、兼容分支或自动回退。固定 dispatcher 位于既有 `evaluator/` 内。保持 CLI、Broker、Snapshot、Finalize、Profile 和非 Workspace 归档合同。Pi 使用 `@earendil-works/pi-coding-agent` 1.5.2；Profile 仍执行并留下统计记录，但不消耗 `evaluate` 预算。

**验证范围：** 本 Plan 只验证实际删除或修改的路径，以及受其影响的现行安全合同。不得把 `evaluator/tests` 整目录通过设为门槛；Plan 01–03 已通过且本 Plan 未改动的测试不重复运行。

**依赖：** Plan 01–03 全部通过。

**Pi 版本已确认：** 2026-11-13 当前宿主已将全局 `@earendil-works/pi-coding-agent` 更新为 1.5.2；`pi --version` 返回 `1.5.2`，`pi --help` 正常退出。Plan 执行时仍须对实际解析到的 `pi` 入口重做这两项轻量检查；不重复安装，也不为版本确认调用模型。当前 Node.js 为 22.23.1，满足该包 `>=22.19.0` 的要求。

**Tech Stack：** Python、pytest、Linux 只读文件视图检查与 Git。

**Spec：** [`00-overview.md`](00-overview.md)，尤其是唯一运行路径、历史 Session 处理与最终验收条件。

## 全局约束

- 只删除 PTOBench 自有的旧身份/导出路径；保留 Candidate Worker、Snapshot、Action freeze、Session integrity 与非 Workspace 归档机制。特别保留或按新目录调整 `evaluator/sandbox_supervisor.py::copy_tree` 对 `agent/native`、CANNBot session/dispatch/tool 记录的活动归档调用；它与旧 `Broker.export/sync_source/feedback` 不是同一路径。删除旧调用前用 `rg` 确认其调用者并更新对应归档测试。
- 不改 Case、Fixture、Seed、Reference、Baseline、CV、`case_selection/` 或用户历史数据。
- `lightweight_e2e` 不得成为正式源码、测试、启动、打包或部署依赖。
- Plan 03 的最终记录已将混合测试结果分类：11 项只覆盖已退役后端或伪造 Pi bundle 的旧测试，交由本 Plan 删除或改写；CANNBot fixture 路径错误已单独修复并通过。不得重跑该混合测试命令，也不得让已退役正向路径测试阻塞验收。
- 仍代表现行合同的失败必须修复或证明是测试本身缺陷；仅与已删除功能绑定的测试应删除。与本 Plan 无关的环境/fixture 失败记录为非门槛，不扩大测试范围。
- `max_hardware_actions` 只限制通过 PTOBench CLI 接受的 `evaluate`。每个已接受的 Evaluate reservation 都消耗一次，包括失败和中断；不得退款。`profile` 不消耗 Evaluate 额度，即使额度耗尽，只要 Session 尚未关闭或失败，仍可执行；它的 mode、attempt、结果/错误、诊断产物及硬件动作统计照常记录。`fork` 不消耗 Evaluate 额度，`finish_actions` 保持独立。
- 不改变 Session/event schema，也不增加持久化计数器。`usage.hardware_actions`、事件中的 `hardware_actions_used` 和 `hardware_action=true` 事件继续统计所有已接受的 Evaluate/Profile 硬件动作，因此该统计值可以大于 `max_hardware_actions`。Evaluate 额度从 `action == "evaluate" and hardware_action is true` 的事件数，加上当前活动的 Evaluate reservation 推导；`remaining_hardware_actions` 和 Evaluate 拒绝规则只使用这个派生数。原有 Session 按事件历史应用同一规则，不批量改写数据。
- `status == "exhausted"` 表示 Evaluate 额度已用完，不是 Session 关闭：不能再接受 Evaluate，但仍接受 Profile 和不耗额度的 Fork；Finish 仍由独立规则处理。不得因 Evaluate 额度耗尽而自动终止 Agent 进程；CLI 拒绝额外 Evaluate，Agent 可继续 Profile/Fork，直至自然退出或被用户中断。`_validate_record` 只校验 status 的枚举值，不再用 aggregate `usage.hardware_actions` 推导它；`_events` 验证 Evaluate 数不超过上限，并保留旧规则下因 Profile 而 exhausted 的记录。Launcher `status` 从事件推导有效的 running/exhausted 状态；接受新的 Evaluate/Profile reservation 时也按 Evaluate 计数更新记录状态，不做批量 Session 写回。
- Pi 1.5.2 的 Plan 04 检查限于真实 `pi` 入口的版本与帮助启动，以及确实受本 Plan 改动影响的 Pi 启动合同测试；不运行全量 Pi/backend 测试、不调用模型/API、不启动 Case 或 NPU。需要模型和真实 Case 的 Pi 集成验收由 Plan 05 承担。

## Review Focus

- 旧 Session 在任何完整性自动修复前拒绝，拒绝前后整棵 Session 树 hash 相同。
- 搜索结果必须区分 PTOBench 自有旧代码、负向测试、历史文档与 vendor 内容，避免误删。

- Evaluate 额度耗尽不得让 Launcher 杀掉 Agent；额外 Evaluate 在 CLI 被拒绝，Agent 仍可完成 Profile/Fork 并自然退出或由用户中断。

- evaluate-only 预算边界：Profile 次数不能减少 Evaluate 额度；额度耗尽后 Profile 仍可执行和留档，而再次 Evaluate 必须在启动 Evaluator 前被拒绝。覆盖 Combined 默认路径、一个 split 样例、失败 Profile 和 Launcher 统计，不为每个 Profile 子模式复制预算测试。
