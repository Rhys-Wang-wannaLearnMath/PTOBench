# PTOAnalyzer Stage 2 任务清单

> Stage 2 执行记录：代码修缮和 CPU-only 验证已完成；16 份既有归档离线回放与代表性原始事实抽查见配套报告。没有运行 PTOBench、NPU 或 Agent 实验。

## 目标

把九个 Micro-tool 改成轻量、只读的性能证据整理器：摘要覆盖全部获准工具和全部可解析数据，明细按需分页；输出原始事实、全量统计、数据来源和解释边界，不给“发现瓶颈/没有瓶颈”一类总括判断。

## 0. 盘点与范围

- [x] 阅读 PTOAnalyzer README、Stage 1 回放、当前 `toolset.py`、`profile.py`、诊断模块和测试。
- [x] 复核 `initial_findings` 的全部调用点；当前仓库内仅见 PTOAnalyzer 自身 README、工具会话和测试，实施时同步迁移为 `initial_summary`。
- [x] 选择现有 16 份 combined Profile 的离线样本，至少覆盖单卡、双卡和 8 卡；优先复用高基数样本。
- [x] 对照 `references/ANALYSIS.md`，确认九项工具各自的输入、关联条件、全量摘要维度和分页明细。

## 1. 统一事实输出

- [x] 删除现有 Tool 级总括状态字段，用观测、来源覆盖和解释边界表达结果。
- [x] 用 `source_coverage` 表达输入处理事实：按来源族列出必需性、文件发现/读取/空/不可读数、记录数、解析/拒收数和具体问题。
- [x] 用 `observations` 表达性能事实与直接计算的统计；每项给出单位、范围、聚合口径、样本数和来源。
- [x] 用 `limitations` 说明当前字段的可解释边界；不写根因、优化处方、置信度、严重度、评级或阈值判断。
- [x] 对没有观测记录的情况，同时展示观测为空及来源覆盖，区分“没有此类记录”和“没有读到数据”。不把缺失、空、格式不识别或解析失败填成零。
- [x] 对跨文件统计，核实 Candidate、Profile、设备、单位、时间窗口和身份关联；未核实的部分只陈述各自事实，不强行 join。

**验收：** 每条输出可由对应原始来源复核；数据处理问题是具体事实，不会伪装成性能判决。

## 2. Tuner 初始摘要与明细访问

- [x] 将 `ToolSession.initial_findings` 改为 `initial_summary`；只包含当前 Tuner 获准的三个 Tool。
- [x] 每个 Tuner 的摘要完整说明三个工具各自分析的内容、数据覆盖和全量统计；不静默省略 Tool、来源或类别。
- [x] 全量摘要由全部可解析记录计算。不得用 Top-K、首屏记录、样例或字符截断替代完整统计；若列出样例，标明样例数与总数。
- [x] 对高基数明细提供稳定排序分页：默认每页 20 条、最多 50 条，返回总数、已返回数与下一页位置。
- [x] 仅为确有高基数明细的 Tool 增加分页；固定、短小的结果不套用复杂查询参数。
- [x] 摘要统计覆盖全量，分页仅用于查阅明细，不能改变统计口径。

**验收：** 多卡高基数 Profile 的初始摘要仍精简且全量；分页遍历无重复、无遗漏，合计与全量数据一致。

## 3. 九个 Tool 按参考逐项收敛

- [x] `compute_mapping_check`：分阶段汇总映射覆盖与关联结果；未验证 Candidate 源码链时，不输出源码位置。
- [x] `compute_unit_activity`：按 build/rank/dispatch/core type 汇总各 PMU counter 和 per-core 分布；保留原单位，不套用外部利用率公式。
- [x] `compute_task_share`：只按已验证的同 dispatch 身份关联汇总；PMU cycles 与运行区间跨度分开统计，报告未关联数及原因。
- [x] `tile_access_check`：完整汇总 compiler hint 类别、位置和来源；保留提示原文，不转成优化处方。
- [x] `buffer_pressure_check`：MemoryReuse hint 与 Scope 原生字段分层汇总；容量语义未验证时，不计算压力百分比。
- [x] `pipeline_overlap_check`：先审计阶段区间、时基和身份；若不能提供独立于 Buffer 的证据价值，暂缓对 Tuner 暴露。
- [x] `dependency_path_check`：规范化节点/边并统计图结构；无 runtime 权重时仅报告无权图事实。
- [x] `dispatch_gap_check`：仅在同 rank/device/core、可信时基和足够覆盖下计算相邻区间空档；只称观测空档，不归因为派发/调度开销。
- [x] `task_distribution_check`：汇总 rank/core 记录数与区间分布；区分 tuple 行、唯一 task 和区间跨度，不据此断言 occupancy 或失衡。

**验收：** 九项工具均有全量摘要、来源和解释边界；任何不可验证的映射、单位、身份或覆盖均明确展示，不输出推断结论。

## 4. 时间类数据审计

- [x] 从实际 Artifact Index 核实 raw/merged swimlane 的文件族、名称后缀和覆盖范围。
- [x] 查明 tuple 字段、rank/device/core、Task/Block 身份、单位、时钟锚点及 raw/merged 对应关系；未知字段不按数组位置猜测。
- [x] 对 gap 统计建立可由原始区间手工复算的例子；跨 rank 只有时钟同步误差经过验证才比较。
- [x] 对 overlap 确认是否存在同一 Candidate、设备、采集窗口下可关联的 Compute/MTE 起止区间。
- [x] 不把编译 pass 耗时、PMU 汇总计数或普通 task 总区间当成 overlap 证据。
- [x] 若字段或语义不足，输出具体覆盖/解析事实与缺少的证据；收窄或暂停工具，不用新 Case 掩盖采集字段缺口。

**验收：** 所有时间统计都可从身份、窗口、单位明确的原始区间复算；不能计算时不输出派生数值或根因解释。
